# 改进计划工作流（模块设计提示词）

适用范围：任何项目、任何语言。把本文件全文粘给该项目的 AI（Cursor / Claude / Copilot 等），按需替换项目相关描述即可。

它的本质是一个信任回路：AI 提出改进点 → 人逐条审核 → AI 执行已通过的 → AI 回填结果 → 人复核。人只在两个关键点把关：审核（做什么）与验收（做得对不对），其余交给 AI 自动流转。

## 一、核心思路

1. 计划点是唯一工作单元：一个功能点一条，包含「标题」和 Markdown 详情，详情固定三段结构——现状（为什么做）、方案（怎么做）、验收（怎么算做完）。
2. 状态机是纪律的载体，由系统而非人保证：待审核 → 已通过 → 执行中 → 已完成；驳回是旁路，可修订后重新进入。
3. 审核不可绕过：批准/驳回只能走审核动作，编辑接口永远无权直接把条目改成"已通过"。
4. 稳定 ID：每个计划点有固定 ID，问题追踪、AI 回填、去重都靠它，重复执行不产生重复条目。
5. 来源透明：每个条目标记是「AI 提出」还是「人手动新增」，责任可追溯。
6. 一切内容以文本流转：详情是 Markdown，复制出去就是可直接粘给 AI 的指令，粘回来的结果按 ID 回填。

## 二、状态机（系统强制）

- 待审核 proposed：AI 或人提出后的初始态。只有审核动作能改变它。
- 已通过 approved：人批准后进入，是执行方唯一有权读取并执行的状态。
- 执行中 in_progress：执行方开工时标记，表示"有人认领了"。
- 已完成 done：终态。执行方回填「执行结果」说明后进入，不可再改状态（内容仍可修订）。
- 已驳回 rejected：必须附原因。允许：改判为已通过（再审核）、退回待审核（修订后重提）。
- 非法迁移（如待审核直接跳到执行中/已完成、已完成复活）一律拒绝并给出可读错误。

## 三、页面与流程

### 1. 列表页（主视图）
- 顶部：标题 + 概览计数（"N 条待审核 · 共 M 条"）+ 两个全局按钮：「新增计划点」和「复制执行中」（见第 5 步）。
- 筛选区：状态选项卡（每个 tab 带实时计数：全部/待审核/已通过/执行中/已完成/已驳回）+ 搜索框（防抖，匹配标题/详情/审核意见/执行结果）。
- 列表：按"待审核优先，同级内高优先级、新条目靠前"排序；行内展示标题+摘要、优先级徽标、来源、状态徽标、更新时间、状态相关动作；超过一屏时分页（每页约 20 条）。
- 行内动作随状态变化：
  - 待审核 → 通过 / 驳回 / 编辑 / 删除
  - 已通过 → 开始执行 / 编辑 / 删除
  - 执行中 → 标记完成 / 编辑 / 删除
  - 已完成 → （无状态动作）
  - 已驳回 → 通过（改判）/ 驳回 / 编辑 / 删除

### 2. 详情弹窗（点击行或标题打开）
- 元信息行：状态徽标 + 优先级 + 来源 + 更新/审核时间。
- 正文：Markdown 渲染（小节/加粗/列表/行内代码/链接），渲染前先整体转义再生成标签，杜绝注入。
- 底部附块：审核意见、执行结果（有则显示）。
- 动作与行内一致，另加「复制全文」：输出标准 Markdown（# 标题 + 元信息 + 审核意见/执行结果 + 正文），一键粘贴给任何 AI。

### 3. 新增 / 编辑表单（弹窗）
- 三个字段：标题（必填）、优先级（高中低）、详情（大输入区，Markdown）。
- 占位提示示范三段结构，引导 AI 和人写出可审核、可验收的内容。

### 4. 审核弹窗
- 显示目标条目标题；意见框下方放「快捷理由」按钮组（可多选，点选拼接进意见框，再点取消选，手动输入保留）。理由用真实高频结论，例如：
  - 通过：「通过，按方案执行」「通过，先做核心部分」
  - 驳回：「范围太大，先拆成小步」「验收标准不够具体」「与现有功能重复」「优先级不足，暂缓」
- 驳回时原因必填（系统校验），通过时意见选填。

### 5. 「复制执行中」简报（给执行方 AI 的任务书）
- 一键把全部「执行中」条目整理为纯文本：序号 + 标题 + 优先级 + 稳定 ID + 去掉 Markdown 修饰的现状/方案/验收 + "完成后按 ID 回填已完成"的提示。
- 空列表时给出引导提示（先在行内点开始执行）。

### 6. 执行循环（AI 的工作方式，写进模块说明）
- 执行方只读「已通过」清单；开工先标「执行中」；严格按「方案」实现，对照「验收」自查；全部验收通过才标「已完成」并回填执行结果。
- 执行中发现方案有问题：不硬做，退回「待审核」并写明原因，等重新审核。
- 执行方永远不能自己批准自己的计划。

## 四、通用设计约束（实现时遵守）

- 每个动作都有明确的服务端校验（状态迁移、必填项、长度上限），错误信息说人话。
- 列表数据量有上限护栏（如 200 条，超限裁剪最老的已完成/已驳回，不丢待处理）。
- 所有展示内容一律转义后输出；用户内容与系统 UI 永远隔离。
- 待审核条目在列表中永远置顶可见，删除动作需二次确认。
- 数据可整体导出（一份 JSON/文档即可迁移）。

## 五、验收清单

- 状态机：非法迁移被拒；驳回无原因被拒；已完成不可复活。
- 审核闭环：AI 无法绕过审核；驳回后修订可重提；改判留痕（审核时间）。
- 列表体验：筛选计数准确；搜索命中标题/详情/意见；分页正确。
- 复制链路：详情复制与执行中简报粘给 AI 后，AI 能凭稳定 ID 完成回填。
- 安全：转义优先渲染无注入；权限校验齐全；只读操作不产生副作用。

## 附：日常循环提示词（每个工作周期粘贴）

读取「已通过」状态的计划点，逐条执行：
1. 先标记「执行中」，一次聚焦一条；
2. 严格按「方案」实现，对照「验收」逐条自查；
3. 项目测试/自检全绿后标记「已完成」并回填执行结果（做了什么、验收结论）；
4. 方案有问题就退回「待审核」写明原因，不硬做；
5. 全部完成后汇报验收对照，并列出剩余「待审核」条目等我审。

不要自行批准自己的计划。
