# 备份恢复与版本交付

适用版本：1.1.0。入口：**产品设置 → 数据与交付**。本说明不记录任何客户实例信息；填写后的交付摘要、资产文件和截图保存在仓库外。

## 1. 三种文件怎么选

| 文件 | 用途 | 包含 | 排除 |
| --- | --- | --- | --- |
| JSON 资产文件 / 服务器备份 | 资料迁移、误操作后恢复 | 域名资料、手工 IP、用途备注、网站链接、人工关联、原有日期和来源标识 | 登录配置、云凭据、API 密钥、云原始响应、自动发现 IP 的检查缓存、操作日志 |
| CSV 资产表 | 用 Excel 等工具核对和交接 | 类型、地址、名称 / 来源、到期日期、备注、IP 网站链接 | 密钥、检查历史、可直接恢复的关联结构 |
| Markdown 交付摘要 | 留存版本与人工验收事项 | 生成时间、版本、资产数量、环境检查、最近备份校验值、空白人工验收项 | 具体域名 / IP 清单、凭据和完成验收的自动承诺 |

JSON 和 CSV 返回内容与 SHA-256，浏览器生成下载文件。服务器备份保存在私有的 `data/backups/`，文件权限 0600、目录 0700。**资产文件仍是私有资料**，不上传公开仓库或作为客服公开附件；校验值用于核对文件完整性，不等于数字签名或加密。

CSV 带 UTF-8 BOM，对公式前缀做文本转义，保留中文、逗号及换行。CSV 目前只有导出，没有 CSV / Excel 导入或逐行合并功能。迁移使用本产品的 JSON 资产文件。

## 2. 创建与管理备份

1. 点击“创建服务器备份”，检查备份时间及域名、手工 IP、关联数量。
2. 点击“下载”，将文件保存到与服务器独立的私有位置；核对 SHA-256。
3. 整理资产、升级版本或进行大量修改前再创建一份。
4. 最多保存 30 份，达到上限会停止创建；没有静默自动淘汰。先下载需要保留的旧文件，再明确删除一份。恢复时也要留出一个空位，以便自动留底。

单份备份 / 迁移文件最大 5 MB，单次恢复最多 10,000 条域名和 10,000 条手工 IP、每个域名最多 100 条人工 IP 关联。这些是输入保护上限，不是经过认证的性能容量。超过范围由维护人员安排受保护的文件级备份与迁移。

## 3. 恢复流程与影响

1. 在备份列表点击“恢复预览”，或选择 JSON 文件后点击“预览文件”。
2. 核对当前与恢复后的三项数量、文件校验值，以及来源转换提示。
3. 输入当前管理员密码及“恢复资产”，再点击替换按钮。
4. 系统先保留恢复前的资产备份，然后替换域名、手工 IP 与人工绑定，清空资产健康、旧版访问及解析记录访问检查结果，并重置同步时间。
5. 回到列表抽查用途备注、网站入口、关联对象；重新执行需要的检查。

**恢复会全量替换，不做增量合并，也不修改云端 DNS。** 检查缓存和自动发现但未登记的 IP 不进入迁移文件；它们会在后续检查或读取 DNS 快照时重新出现。已有 DNS 记录文件快照不由恢复修改，需要时显式刷新云端记录。

预览绑定当前管理员会话，有效期 15 分钟，成功后只能使用一次。预览后资产、同步元数据或检查结果发生变化时，会拒绝提交，需重新预览。预览不会占用长期数据锁；恢复提交期间使用统一资产锁。

恢复前已经开始、恢复后才完成的健康检查、访问检查和域名同步结果会被丢弃，避免把恢复前的结果重新写回。发生进程中断且恢复未提交时，下次访问会按私有恢复日志回滚。该机制用于本机文件系统上的中断保护，不承诺抵御磁盘损坏或跨机器共享文件系统故障。

若恢复失败，不要反复提交修改后的文件；先刷新列表与操作记录，核对恢复前备份及服务器日志，再由维护人员处理。

## 4. 换机与来源转换

资产备份不会搬迁云账号配置。原云账号 ID 在目标实例仍存在时保留来源；不存在时，该来源下的域名转为手工资产，显示原来源名称，并调整人工绑定的域名标识。

若多个旧来源的同一域名转为手工资产后形成重复，预览会拒绝并提示整理资料，不会静默覆盖。已删除域名留下的残留关联会明确计数并忽略。

客户在新实例重新配置云账号与凭据后再同步，可能同时存在手工资产和云来源资产，应逐项核对后整理；当前没有自动合并来源能力。API 密钥需要在新实例重新创建。

## 5. 升级与完整实例回退

界面里的资产备份不包含登录信息、云凭据或 API 密钥，不能代替完整实例备份。完整备份由维护人员在暂停写入后，用客户认可的受保护备份方式复制实际配置、整个 `data/` 及当前程序版本，保存到网站目录、代码仓库和发行目录之外；加密与保管责任在交付时明确。

建议升级步骤：

1. 记录当前版本、维护窗口和回退条件，暂停检查、同步及其他写操作。
2. 下载资产备份，并完成受保护的完整实例备份；在隔离实例验证能够读取。
3. 核对新 ZIP 的 SHA-256 和包内 `manifest.json`；程序部署到独立版本目录，保留旧程序。
4. 保留实际配置和数据的属主与权限，在隔离环境先升级，再切换生产程序目录。
5. 新会话登录，核对数量、关键字段、人工绑定、只读 API、环境自检；明确执行一次受控检查。
6. 不通过验收时先暂停写入，再恢复旧程序及其匹配的数据、配置。不要仅恢复程序并假定新旧数据结构必然兼容。

仅通过 JSON 恢复资产不会更改现有登录或 API 授权。完整实例换机或备份疑似外泄时，管理员更新登录信息以使旧 Session / API 密钥失效，并按云商流程轮换云凭据。

## 6. 生产部署与发布包

使用仍受维护的 PHP 版本，启用 curl、mbstring、json、openssl；域名健康检查还依赖 PHP CLI 与可用的 `proc_open`。首次配置应在受控网络完成。

生产服务把网站根目录**严格指向 public**，使用 HTTPS 与 PHP-FPM。[Nginx 配置示例](../../deploy/nginx.conf.example) 需要在客户环境替换部署路径、证书和 PHP-FPM Socket，保留只有单入口可执行的限制。反向代理的 HTTPS 标识由可信服务端配置，应用不会直接信任任意客户端转发头。当前没有在客户服务器自动安装证书或验证 Nginx 上线配置。

本地 `./start.sh` 默认只监听 `127.0.0.1:8080`。需要局域网开发时显式设置 `WORKSPACE_HOST` / `WORKSPACE_PORT`；开发服务器不作为生产部署方案。

生成来源文件白名单发行包：

```sh
python3 scripts/check-public-docs.py
python3 scripts/package-release.py --output-dir dist
```

脚本先校验公开文档，收集 `app/`、受允许类型的 `public/`、编号 Markdown 文档、生产配置示例及指定脚本；拒绝符号链接和未知附件。不会遍历 `data/`、实际配置、`.local/`、历史 ZIP、Git 历史或测试运行目录。输出版本 ZIP、ZIP 的 `.sha256` 和包内文件清单；默认不覆盖旧包。

发布包的文件白名单不是源代码秘密扫描器，维护者仍需审查程序中的硬编码信息。代码与素材授权、正式服务条款、客户生产验收需要单独确认；构建成功不等于已经批准公开售卖。

## 7. 验收与维护

至少完成一次隔离演练：导出 → 修改一条合成备注 → 预览 → 发现数量与范围 → 恢复 → 核对备注、链接、关联 → 查看自动留底与操作记录 → 确认原 API 权限没有扩大。

基础操作记录保留最近 1,000 条，页面展示最近 100 条。它记录通过权限校验后的写请求，包括浏览器及 API 来源、路由、路径目标、操作者和完成结果，不记录请求正文、密码、Token 或 DNS 前后差异。登录失败、未通过权限校验的请求不属于当前记录范围；“处理中 / 待核实”表示没有完成记录，不保证操作尚未发生。服务器拥有者可修改文件，不能宣传为合规或不可篡改审计。

维护人员定期下载备份并核对存储空间。交付摘要的人工验收框默认不勾选，只有完成客户环境验证后再在私有交接记录中确认。
