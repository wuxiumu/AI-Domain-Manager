# 登录防护与限流

适用版本：1.1.1 起。入口：工作台登录页。验证码由服务器本地生成，无需第三方账号、联网请求或 GD 扩展。

## 使用方式

填写账号、密码和图片中的 5 位字符，不区分大小写。图片两分钟有效，点击图片可更换；过期时页面自动获取新图片。每次登录提交后验证码作废，密码错误也需要填写新图片。登录失败清空密码和验证码，保留账号。

验证码绑定当前浏览器会话，刷新图片后旧标识失效。同一会话同时打开多个登录页时，以最后获取的图片为准。服务器只保存答案散列，接口不返回答案；SVG 使用图形路径绘制字符。

## 服务端限制

| 操作 | 同一 IP 限制 | 超限行为 |
| --- | --- | --- |
| 获取验证码 | 每 60 秒最多 30 次 | HTTP 429，返回剩余等待秒数 |
| 提交登录 | 每 60 秒最多 10 次，成功提交也计入 | HTTP 429，等待当前窗口结束 |
| 登录失败 | 从第一次失败起 300 秒内累计 5 次 | 第 5 次立即锁定 300 秒 |

缺少或错误验证码、过期验证码、无效 CSRF、错误账号密码均计入登录失败。成功登录清除失败累计，仍保留一分钟提交次数。锁定到期后重置失败累计；锁定期间的提交不会延长原锁定时间。换账号、清 Cookie、换浏览器不能重置同一 IP 的限制。

服务端返回 `code: rate_limited`、`retry_after` 及 `Retry-After` 响应头，页面据此禁用登录与图片刷新，并显示倒计时。刷新页面不会解除服务器锁定；等待期间应避免反复提交。

限流以连接来源 `REMOTE_ADDR` 为准，不直接信任客户端提供的转发头。使用反向代理时，由管理员在 Web 服务器中配置可信代理和真实客户端 IP；未配置时，代理后用户可能共用同一个限额。不要将任意来源的转发头直接传成可信客户端地址。

## API 与自动化

1. `GET /api/login/captcha`，保存 Cookie，读取 `image`、`captcha_id`、`expires_in`、`expires_at` 和 `csrf_token`。
2. 将图片显示给使用者，人工输入验证码。
3. `POST /api/login`，保留相同 Cookie，将 `csrf_token` 放入 `X-CSRF-Token`，JSON 包含 `user`、`pass`、`captcha_id`、`captcha`。
4. 成功后保留轮换后的 Cookie，后续写请求使用新返回的 CSRF Token。失败需重新获取验证码，HTTP 429 先按等待时间退避。

登录与图片响应均为 `Cache-Control: no-store`。旧版仅发送账号密码的调用需升级；不存在免验证码的密码登录接口。`scripts/workspace-api.py --username` 仅支持交互式密码和验证码；无人值守任务使用有有效期、可撤销且范围明确的 Bearer API 密钥。

## 部署与维护

限流存储为文档根目录之外的 `data/login_limits.json`，通过稳定文件锁完成读取、校验与写入，供同一实例的 PHP 进程共享；文件权限为 0600，键为来源地址的散列，不保存密码或验证码答案。过期记录在后续请求中清理，最多保留 10,000 个有效预算项；容量满时，新来源需稍后重试。

确保 PHP 运行账号可写 `data/`、PHP Session 目录可用。限流文件损坏或不可写时请求失败，不跳过校验放行。不要通过删除生产限流文件作为日常解锁方式。当前实现面向单实例文件部署；多个独立节点需要共享可靠的限流服务后再扩容。

升级沿用已有管理员配置，无需重新初始化。新增限流文件独立于旧版失败计数文件，升级后从新的计数窗口开始；已有资产备份与恢复不包含或覆盖登录限制和会话。

## 验收

使用临时安装与合成数据进行验证，不能用客户实例进行批量失败测试。

```sh
php tests/auth_test.php
python3 tests/auth_api_test.py
python3 tests/product_api_test.py
node --test tests/login_ui_test.mjs tests/api_test.mjs
python3 scripts/check-public-docs.py
```

覆盖正确与错误验证码、过期、重放、跨会话、CSRF、Session 轮换、错误密码、换 Cookie 与伪造代理头、限流恢复及多个 PHP 进程并发。HTTP 测试只操作临时安装的私有会话，用已知答案构造验证条件；生产代码没有测试开关或验证码答案接口。
