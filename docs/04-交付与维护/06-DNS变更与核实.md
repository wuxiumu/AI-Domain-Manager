# DNS 变更与核实

适用版本：1.2.0 起。入口：域名管理的完整 DNS 管理、域名详情中的快捷编辑，以及产品设置 → 数据与交付 → DNS 变更记录。

## 操作流程

1. 打开 DNS 记录，按需要填写新值或选择待删除记录。
2. 点击“预览变更”，核对云账号、域名、主机记录，以及类型、值、TTL、优先级和线路的前后差异。返回修改不会写入云端。
3. 确认提交后，服务器先读取云端最新记录。若旧值版本已改变，返回冲突，本次不写入，需刷新后重新确认。
4. 写请求只发送一次，随后重新读取云端。界面区分“云端已核实”“无需变更”和“待核实”。

新增同样需要确认当前区域版本，防止在过时列表上反复新增。批量操作先统一预览，再逐条提交；遇到错误或待核实结果时停止后续请求，显示已核实、待核实、未执行数量。关闭操作窗口后不再提交后续记录。已完成的云端修改不会自动撤回。

## 结果口径

| 结果 | 含义 | 后续动作 |
| --- | --- | --- |
| HTTP 200、verified 为 true、verified 状态 | 云端回读与预期一致，未选中的原记录仍存在 | 按需要确认实际解析传播 |
| HTTP 200、unchanged 状态 | 云端当前值与拟提交值一致，没有发送写请求 | 无需重复提交 |
| HTTP 409 | 记录已改变、已删除或区域版本过期，未发送本次写请求 | 刷新记录，再核对差异 |
| HTTP 422 | 缺少版本条件或参数不符合要求 | 补齐参数，不要绕过版本校验 |
| HTTP 202、verified 为 false | 云请求超时、回读失败、值不一致或后续记录未完成 | 保存 change_id，刷新云端或到云商控制台核对，确认后再决定下一步 |

云端回读确认不代表所有递归 DNS 缓存已更新，也不等于网站业务可用。超时不能推断请求一定没执行，因此系统不自动重试写操作。

## API 变化

`GET /api/domains/{provider}/{domain}/records` 返回每条记录的 `version` 和整个区域的 `revision`。版本基于记录标识、类型、主机名、值、TTL、优先级、线路与状态计算，原始云载荷不参与版本。

- 修改：`PUT .../records/{recordId}`，JSON 传 `expected_version` 及需要修改的字段；省略的字段由服务器从最新原记录保留。
- 删除：`DELETE .../records/{recordId}`，JSON 传 `expected_version`。
- 新增：`POST .../records`，JSON 传 `expected_revision`、`type`、`name`、`value`，可补充 TTL、优先级与线路。
- 查询历史：`GET /api/dns/changes`，仅管理员 Session，不向 Bearer 开放。

Session 写请求仍需 Cookie 和 CSRF；Bearer 写请求仍需 `dns:write`。旧版无条件 DNS 写客户端需要升级，不能把任意字符串当成版本，也不应在冲突后自动读取新版本并重放原修改。

所有写响应都要检查 `verified`。HTTP 202 使用 `ok:true` 表示请求处理结果已返回，其中 `verified:false` 明确表示变更结果未确认；只检查 HTTP 成功或 `ok` 会误报。

## 云商差异

GoDaddy 当前接入使用 v1 的同名同类型记录组接口。删除组内一条时，服务器读取该组，保留其余成员并替换；只有删除最后一条时才调用组删除。无法唯一识别的重复记录会拒绝操作。接口语义依据 [GoDaddy v1 官方参考](https://classic-developer.godaddy.com/doc/endpoint/domains)。

阿里云变更保留原解析线路；依据 [UpdateDomainRecord 官方参数](https://help.aliyun.com/en/dns/api-alidns-2015-01-09-updatedomainrecord)。腾讯云修改保留 MX 优先级、已有停用状态和权重；依据 [ModifyRecord 官方参数](https://cloud.tencent.com/document/product/1427/56157)。云商对 TTL、记录类型、优先级和套餐有各自限制，回读若不符合拟提交值会标为待核实。

同一部署实例的读取与写入使用区域锁，防止本实例的请求互相覆盖。云商控制台和其他独立部署不共享此锁；当前云接口没有由本工作台掌握的跨系统原子事务。因此冲突检查可以发现提交前的变化，不能承诺消除检查与云端写入之间的所有竞态。

长时间的 DNS 网络请求在权限校验后释放 PHP Session 文件锁，避免占住同一浏览器的其他请求。开发入口只执行前置控制器，内部模板不可直接访问；API 参数中的 `.php` 后缀按普通数据处理。生产 Nginx 示例同样将 API 请求统一交给前置控制器。

## 记录与资料边界

DNS 专用记录保存在网站根目录之外的 `data/dns_changes.json`，权限 0600。写入前先保存待处理记录，不能保存时不发送云端修改。完成后更新原值、拟提交值、回读值、操作者、来源、时间和结果。最多保留 200 条，接口和页面返回最近 50 条。

记录排除云商原始载荷、HTTP 请求头、管理员密码和云凭据，但 DNS 值本身可能含私有 TXT 内容或地址，因此仅管理员可读，不能放入公开文档、推广截图或客服附件。普通资产 JSON 导出与恢复不包含 DNS 缓存或此历史；恢复资产也不会回滚云端 DNS。

待处理记录可能来自中断的请求，不等于操作失败。当前提供查看与人工核对，尚无自动对账、自动回滚或无限历史。

## 访问检测边界

域名列表和 DNS 记录的旧访问检测入口现在与安全探测规则一致：只连接校验过的公网地址，固定 DNS 解析结果，不跟随重定向，HTTPS 校验证书链与主机名。不再因 HTTPS 失败自动降级到 HTTP；HTTP 入口仅用于裸 IP 检测。探测直连目标，不沿用云 API 的代理配置，以免代理重新解析目标绕过地址校验。

并发每组最多 20 个目标，DNS 准备与 HTTP 请求各有时间上限。HEAD 返回 405 / 501 时可在同一安全目标内回退 GET，请求范围受限，最多读取 64 KB；不会因为跳转或证书错误继续请求其他地址。3xx 只表示原入口返回跳转，不代表跳转目标正常。

DNS 记录访问结果绑定产生它的 DNS 版本；版本改变后旧结果不展示，检测期间有变更时拒绝旧结果回写。历史版本留下的无版本访问缓存不再当成当前检测结果，需要重新检查。

## 验证

以下命令在源码仓库执行，发行包不含测试夹具。离线验证还覆盖 6 个进程争抢同一旧版本，以及 5,000 条合成记录的同组保留核对；它们不构成生产容量承诺。

```sh
php tests/dns_changes_test.php
php tests/dns_pagination_test.php
php tests/public_probe_test.php
php tests/public_probe_transport_test.php
python3 tests/dns_changes_api_test.py
node --test tests/dns_changes_ui_test.mjs tests/client_cache_test.mjs
```

测试使用临时目录、保留地址与本地云商模拟器，验证冲突拒绝、单次写入、回读不一致、超时、同组保留、前后值、Session / CSRF / Bearer 边界和日志失败。没有读取真实客户资产或执行真实云商写操作。上线前仍需在客户独立测试区域验收权限、类型限制与回读表现。
