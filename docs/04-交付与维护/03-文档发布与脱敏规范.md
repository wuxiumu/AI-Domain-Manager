# 文档发布与脱敏规范

## 1. 分类和编号

- `01-产品介绍`：当前功能、安装与 API、概念说明。
- `02-推广文案`：官网、销售和平台稿件；规划项不能写成已上线能力。
- `03-计划方案`：产品、商业化及运营安排，明确标记待验证假设。
- `04-交付与维护`：空白需求模板、工程维护和发布规范。
- 总入口为 `docs/00-目录.md`，每个分类有 `00-目录.md`。
- 文件与分类目录均以两位数字和连字符开头；新增内容同步更新目录及引用。

## 2. 公开文档可使用什么

| 内容 | 规则 |
| --- | --- |
| 示例域名 | 使用 `example.com`、`example.net`、`example.org` 及其子域名，或 `.test` / `.invalid` 示例 |
| 示例 IPv4 | 使用文档地址段 `192.0.2.0/24`、`198.51.100.0/24`、`203.0.113.0/24` |
| 示例 IPv6 | 使用 `2001:db8::/32` |
| 本机访问 | 使用 `localhost`、`127.0.0.1`、`::1` |
| 账号与 Token | 使用明确占位符，不使用当前配置的别名、ID、凭据片段或真实 Token |
| 数量与时间 | 使用明确标为合成演示的数据；不写实例资产总数、来源账号分布和运行快照时间 |
| 外部资料 | 仅链接公开官方资料，不能把客户控制台、真实站点或私有仓库链接混进文档 |

不要用真实域名配假 IP、真实 IP 配假域名或仅遮住部分字符的方式制作示例。关系本身也可能泄露资产归属，应整套使用独立的合成数据。

## 3. 截图、导出和客户材料

当前文档以文字和 Mermaid 示意图为主，不携带实例截图。旧预览图片已移除，不移动到可提交的归档文件夹。

后续确需图片时，使用没有接入真实账号的演示实例，重新生成素材，并在人工复核和检查规则支持后再加入。OCR 只能辅助，不能据此保证图片没有泄露。

真实截图、台账、日志、导出、已填写的需求表和完整备份放在仓库外，或已忽略的 `.local/` 下；不要提交到 `docs`、测试夹具或发行包。不要把“内部计划”目录误认为访问受限目录。

## 4. 自动检查

在项目根目录执行：

```sh
python3 scripts/check-public-docs.py
python3 -m unittest discover -s tests -p 'public_docs_test.py'
```

检查覆盖当前 `docs` 与根 README：编号、相对链接、可疑地址、部分常见凭据格式、个人绝对路径和不允许的附件。输出只提供文件、行号及规则名称，不回显疑似敏感值。

检查使用公开站点白名单，新增外链需确认用途后维护白名单。GitHub Actions 会在推送和拉取请求时执行相同检查；外部平台是否启用、分支是否要求检查通过，需要仓库维护者在相应平台确认。

自动检查只处理已定义模式，不是完整秘密扫描器。客户名称、业务含义、截图内容和表格中的隐含关系仍需人工复核。生产配置和运行数据不在脚本读取范围内。

## 5. 能力和销售表述

| 不能直接使用的表述 | 当前可用表述 |
| --- | --- |
| 密钥永不落盘 / 已加密存储 | 凭据保存在部署实例的私有配置中，查询不回显完整秘密 |
| 自动提醒 / 实时告警已经可用 | 当前提供到期筛选和手动检查，通知增强项单独评估 |
| AI 自动接管运维 | 提供分权限 API，可验证接入支持相应接口的工具 |
| 展示全部受影响网站 | 查看已登记或观察到的关联，辅助核对范围 |
| IP 正常就是业务正常 | 展示该次 IP HTTP 入口检查结果 |
| 已开源 / 任意商用 | 按实际发布的许可证及交付授权说明 |

未测量的收益、客户数量、故障降低比例和未经许可的客户背书不进入推广稿。报价、排期及规划功能放在计划目录，销售素材只引用正式确认过的范围。

## 6. 已进入 Git 历史的材料

删除或修改当前文件不会删除历史提交、远端分支、标签、旧发行包、平台缓存和他人已经复制的内容。本次目录整理不等于历史清除完成。

如果敏感材料已进入历史，应另行确认受影响的分支、标签、远端和协作人员，再安排历史清理及分发物处理。改写历史和强制推送会影响协作，不在普通文档整理中自动执行。

若曾暴露凭据，应单独处理撤销和轮换；域名或 IP 关联暴露不等于已经发现凭据泄露。复核只记录路径、范围与处理结果，不在修复记录中再次粘贴真实资产。
