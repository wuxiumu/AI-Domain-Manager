# 有没有人让 AI 直接帮你管域名？自托管工作台可以做到

> 适用于：知乎。偏价值与痛点叙述，代码适中，面向技术人群与互联网从业者。

---

做过运维或自己管过站的人应该都有这种感觉：手里几十个域名，分散在阿里云、腾讯云、GoDaddy 好几个账号。要查一个域名解析到哪，登一个控制台；改条记录，再登另一个；想看看哪些域名快到期，只能自己翻表格。

我一度以为是我用工具的方式不对，后来发现，问题是**所有工具都在逼人手动操作**。

现在 AI 已经能写代码、读文档、调接口了。那有没有可能，让它直接帮我把域名管起来？答案是可以的——前提是你得给自己的管理工作台开一个「AI 能读懂、能调用」的口子。

这篇文章讲讲我用的自托管方案，以及一个更重要的观念：**AI 操作你的资产，凭什么放心？**

---

## 为什么不是「让 AI 去点网页」

最直觉的想法是让 AI 模拟人去网页上点按钮。但这条路又慢又脆，页面一改版就失效。

真正靠谱的做法，是给 AI 一份**机器可读的接口契约（OpenAPI 描述）**，让它像调用普通 API 一样，精确、可靠地操作你的资产。这也是现在 AI Agent / MCP 类工具通用的标准做法。

这里就要提到一个自托管工具——**域名管家（Domain Manager）**。它是一个 PHP 全栈自托管工作台，把阿里云、腾讯云、GoDaddy 的域名聚合到一个界面，自带健康看板、资产关系图、DNS 管理和到期提醒。最特别的是，它把「AI 接入」做成了产品能力，而不是事后补丁。

它对 AI 暴露三个东西：

- `GET /api/openapi.json`：OpenAPI 3.1 接口契约，AI 据此知道能调什么
- `GET /llms.txt`：面向 AI 的自然语言操作说明
- `GET /.well-known/asset-workspace.json`：能力发现，让工具自动识别工作台

鉴权用 Bearer Token + 分权限密钥，AI 只能用被授权的范围。

---

## 上手只有三步

**第一步，生成一个分权限的密钥。** 在「产品设置 → AI API」里创建，scope 分得很细：读资产、写资产、读 DNS、改 DNS、跑检查、跑同步。默认只开最安全的「读资产 + 读 DNS」——**AI 默认只能看，不能动**。密钥最长一年，随时可以撤销。

**第二步，把工作台地址和密钥交给 AI。**

```sh
export WORKSPACE_URL='http://127.0.0.1:8080'
export WORKSPACE_API_TOKEN='你创建的密钥'
python3 scripts/workspace-api.py GET /api/domains   # 查所有域名
python3 scripts/workspace-api.py GET /api/health    # 查健康状态
```

**第三步，让 AI 学会「先查后改」。** 约定是先读域名列表拿到 provider（云账号 ID），再读该域名的记录拿到记录 ID，最后才调接口改，且只改你要改的字段。这样每一次操作都有据可查、可审计，不是黑盒点按钮。

---

## 我最想说的是「安全」这件事

AI 能操作你的资产，这件事听起来就让人不放心。但域名管家把安全做进了产品：

- **最小权限**：默认只读，写操作要显式放开。
- **密钥本地保存、不回显**：云凭据存在站点目录之外的私有文件，查询接口不返回，明文只在创建时出现一次。
- **可撤销、有有效期**：密钥随时撤销，到期自动失效。
- **结果不误判**：约定「未检查 / 已过时」不算健康，客户端同时看 HTTP 状态和业务状态——因为有些云接口返回 200 但业务其实失败了。

这套「最小权限 + 可撤销 + 可审计」的模型，恰恰是我觉得 AI 接入工具最该有的样子，比「能操作」本身更重要。

---

## 接入之后，我的日常变化

- 查解析、查到期，一句话秒回，不用登三个控制台。
- 批量改多账号的解析，统一在自托管层操作。
- 结合资产关系图，能直接问「这台服务器挂了影响哪些网站」。
- 同一套接口，我的脚本、CI 也能复用，不只是 AI 能用。

## 适合谁

- 域名多、账号散的个人站长 / 开发者；
- 想自动化资产台账和检查、又不想被 SaaS 绑定的中小团队；
- 用一套自托管工作台批量管多个客户资产的代运维 / 建站服务商。

---

域名管理不该是「登控制台 → 找域名 → 手工改」的重复劳动。给它开一个 OpenAPI 的口子，AI 就能替你管起来——密钥在你手里，权限你说了算。

项目是开源的，可以自己部署体验。详细的 AI 接入配置和授权范围，见项目的产品配置文档。
