# 推广运营计划

状态：待验证方案。本文只安排推广工作，不保存待发布长文、客户联系方式、真实资产或账号信息。

## 目标和顺序

先验证建站、代维及小团队的资产查找与交接需求，再扩大传播。主服务建议是客户自有实例部署、资料整理和使用交接；报价假设见 [商业化方案](02-商业化方案.md)。

## 第一轮执行

| 阶段 | 动作 | 产出 |
| --- | --- | --- |
| 需求访谈 | 与符合画像的用户了解最近一次查找、交接或迁移流程 | 匿名问题归类，不在仓库记客户名单 |
| 演示准备 | 使用合成域名、文档专用 IP 和虚构备注 | 一套可重复演示的数据和脚本 |
| 内容验证 | 选择一个技术社区及一个已有私域渠道试发 | 记录有效咨询与问题，不用曝光量代替需求 |
| 范围报价 | 对愿意继续的客户给相同服务边界的试点报价 | 成交与拒绝原因、实际投入工时 |
| 交付复盘 | 完成验收后回访真实使用情况 | 决定继续投入通知、导入或团队能力 |

建议第一轮目标为 10 次访谈、5 次明确范围报价和 2–3 家付费试点，均为实验目标，不是收入预测。没有访谈或订单证据时，不因其他工具有某功能就直接扩大研发。

## 渠道选择

- 先接触已有关系中的建站与代维团队，围绕具体工作流程做演示。
- 技术文章展示搜索、关联和 API 使用，社交短内容展示资料整理场景。
- 先维护好安装说明和演示，再评估导航站、应用市场等分发渠道。
- 社区帖子遵守所在社区的推广规则；客户案例取得许可且完成脱敏后再制作。

现成素材统一在 [推广文案目录](../02-推广文案/00-目录.md) 维护。不要在计划中重复保存另一份文章，避免版本失配。
