# 本轮落地与后续迭代

日期：2026-10-27。版本：1.2.0。方向：形成单管理员、客户自有实例的交付基础，继续保留列表优先的日常使用方式。

## 已实现

| 优化 | 实际行为 | 对产品和商业交付的价值 |
| --- | --- | --- |
| 资产备份 | 服务器创建、列表、下载、删除，私有目录与权限，上限 30 份 | 实施前能留底，交接时客户可拿走资料 |
| JSON 迁移与恢复 | 5 MB 内导出 / 上传，15 分钟预览，数量和来源变化提示，密码确认，全量替换前自动留底 | 把“可恢复”变成能演示、能验收的流程 |
| 一致性保护 | 统一资产锁，中断恢复日志，预览版本校验，恢复前网络任务结果拒绝回写 | 减少整理资料时互相覆盖的风险 |
| CSV 交接 | 中文表头、UTF-8、备注与网站链接，公式文本转义 | 客户退出、内部对账和线下交接更直接 |
| 基础操作记录 | 浏览器 / API 写入操作者、路由、时间与结果，最近 1,000 条 | 能核对主要维护动作是否执行，不再只靠口头描述 |
| 环境自检与交付摘要 | 管理员会话专用，自检数字醒目，导出版本、数量、备份校验值和人工验收事项 | 标准化售前演示与交付交接材料 |
| 来源文件白名单发布 | 固定版本、ZIP 校验值、包内文件清单、Nginx 示例 | 安装包不夹带运行资产、凭据、旧归档或 Git 历史 |
| 同步可信度 | 全部失败和跳过保留原成功时间，部分成功单独提示 | 避免把旧台账误认为刚成功更新 |
| 登录防护 | 一次性图形验证码、IP 限流、失败锁定与等待倒计时 | 减少无约束密码尝试，自动化使用可撤销 API 密钥 |
| DNS 变更闭环 | 单条与批量差异预览、云端旧值冲突拒绝、写后回读、待核实结果、私有前后值记录 | 降低误改、重复提交与“界面成功但云端未确认”的交付风险 |
| 数据新鲜度 | 健康与统计浏览器缓存一分钟，升级清理旧应用缓存 | 减少长时间显示过时统计或旧接口数据 |

这版没有引入计费、授权服务器或多人体系。报价仍是商业方案中的待验证假设，不会写成已上线订阅。

## 验证范围

备份与恢复服务、非法输入、路径范围、CSV 转义、过期与跨会话预览、数据变化拒绝、中断回滚和旧检查结果拒绝回写已通过离线回归。HTTP 集成覆盖首次安装、Session / CSRF、Bearer 拒绝、密码确认、恢复留底、关联保留、操作记录及 OpenAPI 契约。

合成资产实例已通过浏览器完整恢复流程，未请求真实云商，也未读取或修改客户 / 当前实例的私有资产。没有做生产容量认证或客户 Nginx 部署验收。测试命令见 [安装与 API 接入](../01-产品介绍/02-安装与API接入.md#验证)，操作说明见 [备份恢复与版本交付](../04-交付与维护/04-备份恢复与版本交付.md)。

## 尚需完成的交付门槛

- DNS 变更流程已通过模拟器与接口验证；还需在客户独立测试区域验收云商权限、套餐限制和实际回读表现，不能承诺跨控制台的原子事务或全球解析立即生效。
- 客户生产环境的隔离恢复演练、云账号最小权限说明、实际访问控制与受保护的完整实例备份。
- 代码、图标、字体等素材来源与授权范围，正式报价和服务条款。
- 部署规模与检查规模的可重复基准，不能用输入上限代替容量承诺。

因此第一阶段仍定位为**有限范围的单实例试点**。不要直接宣传为成熟监控 SaaS 或完整企业资产平台。

## 下一轮顺序

1. **DNS 客户环境验收**：闭环已落地，先使用独立测试区域验证云商权限、路由、TTL 和回读表现，记录异常处理方法。
2. **客户台账迁入**：CSV / Excel 逐行预览、错误和重复报告、可控合并，再补客户 / 项目 / 负责人筛选。
3. **后台检查**：持久化任务、CLI Worker、重启中断处理、页面关闭后继续，保留当前手动模式。
4. **一个通知渠道**：异常、恢复、通知失败与重试可核对，验证持续付费后再做团队版。

商业上先沿用“部署 + 资料整理 + 交接”的试点方案，以相同范围记录真实实施工时与验收反馈。产品改进优先选择能减少交付工时、避免资料丢失或让客户持续回访的需求。
