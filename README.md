# 资产工作台 · Asset Workspace

**把分散的域名、IP 和网站资料放到一起，让资产关系与检查结果一目了然。**

资产工作台是一款可自行部署的 PHP 资产管理工具，适合管理多个域名、服务器或网站的个人与小团队。它将云账号中的域名和手工登记的 IP 汇总成一份可搜索的台账，并提供 DNS 管理、关系查看和按需检查。

[快速开始](#快速开始) · [产品能做什么](#产品能做什么) · [使用流程](#一个典型的使用流程) · [架构设计](#架构设计) · [详细文档](docs/00-目录.md)

> 当前版本：1.2.0。项目以单管理员、自行部署为定位；示例和截图中的资产均为合成数据。

## 为什么需要它

当域名分散在不同云账号，IP 和网站用途分别记录在表格、聊天记录或个人笔记中时，查找信息和交接都容易花费时间。资产工作台把这些资料放到同一个界面，让你能够回答：

| 常见问题 | 工作台如何帮助 |
| --- | --- |
| 我有哪些域名和 IP？ | 同步云账号域名，也可以手工维护域名及公网 IP。 |
| 这个域名或 IP 用来做什么？ | 记录用途、备注和网站链接，并通过搜索快速查找。 |
| 域名和服务器之间有什么关系？ | 展示 DNS 观察到的关系和人工确认的绑定。 |
| 资产目前是否可以访问？ | 手动运行检查，查看状态、时间和结果证据。 |
| 如何接入脚本或外部工具？ | 通过带权限范围和期限的 API 密钥访问 OpenAPI 接口。 |

## 产品能做什么

| 模块 | 主要能力 |
| --- | --- |
| 健康看板 | 以卡片汇总问题中心与检查趋势的概况，主体为域名与 IP 列表、检查结果与状态分布；支持搜索、筛选、按需检查，并可一键生成交给 AI 分析的 Markdown 报告。 |
| 问题中心 | 独立页面聚合全部待处理事项（可达性只看 HTTP），按 P0 / P1 / P2 分级，可按类型筛选并一键批量检查。 |
| HTTPS 跟进 | 独立页面汇总 HTTPS 证书验证失败、HTTPS 未确认与证据过时的域名，专项跟进，不影响可达性判定。 |
| 检查趋势 | 独立页面展示近 30 天检查趋势图（每日检查数、正常 / 异常、平均延迟）与每日明细。 |
| 检查日历 | 按日期选择心情、写一句话、维护待办；通过分类查看资产状态及检查记录。 |
| 资产关系 | 按域名或服务器切换查看关系与状态统计，区分 DNS 观察与人工绑定。 |
| 域名管理 | 手工维护域名资料，或从阿里云、腾讯云和 GoDaddy 多账号同步。 |
| DNS 管理 | 查看及修改解析记录；变更前核对版本，提交后回读并记录结果。 |
| IP 资产 | 登记公网 IPv4 / IPv6，维护名称、用途、备注和网站链接。 |
| 云账号与设置 | 维护云账号、测试连接、配置网络代理及管理员登录信息。 |
| 数据清理 | 产品设置内集中清理账号不可用的遗留域名记录（整组删除或转为手工，连带 DNS 缓存与健康残留），四类日志（检查历史、DNS 变更、操作记录、同步日志）按域名 / 账号 / 类型 / 时间维度删除。 |
| 数据与交付 | 资产备份、JSON 导出与恢复预览、CSV 导出、部署自检和操作记录。 |
| API 接入 | 提供 OpenAPI 3.1 描述和可设定权限、有效期的 API 密钥；AI 可读取交接简报、提交 DNS 变更提案，由管理员批准后执行。 |

## 一个典型的使用流程

```mermaid
flowchart LR
    A[创建管理员] --> B[连接云账号<br/>或手工登记资产]
    B --> C[同步域名 / 录入 IP]
    C --> D[补充用途、备注和网站链接]
    D --> E[查看资产关系]
    E --> F[按需检查或管理 DNS]
    F --> G[备份与导出]
```

例如：先同步 `example.com`，再登记一台公网 IP 并补充用途；随后在资产关系中核对 DNS 观察到的线索，按实际情况添加人工绑定。需要了解运行状态时，再手动发起检查。

**几个容易混淆的概念：**

- **同步域名**是从云账号读取域名；**刷新 DNS 快照**是读取解析记录；**检查资产**是主动执行网络检测。三者互不等同。
- **DNS 观察**表示解析指向某个 IP，该地址可能是 CDN 或代理入口；**人工绑定**记录的是用户确认的关系。
- 检查结果是某个时间点的证据。未检查和过时结果分别显示，不能视为当前正常。

## 快速开始

### 1. 准备环境

- PHP 7.4 或更高版本，建议 PHP 8.x；安装 `curl`、`mbstring` 扩展。
- 运行检查需要可用的 PHP CLI、`proc_open` 和本机 DNS 解析能力。
- 本地体验可使用 PHP 内置服务器；生产环境请将 Web 根目录指向 `public/`，并配置 HTTPS。

### 2. 启动

在项目根目录运行：

```bash
./start.sh
```

也可以直接启动：

```bash
php -S 127.0.0.1:8080 -t public public/index.php
```

浏览器访问 `http://127.0.0.1:8080`。新安装在页面创建管理员，已有安装沿用原配置。PHP 内置服务器用于本地体验，生产部署请参考 [Nginx 示例](deploy/nginx.conf.example) 和 [安装与 API 接入](docs/01-产品介绍/02-安装与API接入.md)。

### 3. 开始使用

1. 在“云账号”添加账号并测试连接，或直接手工登记资产。
2. 同步域名，按需补充 IP、备注和网站链接。
3. 打开“资产关系”核对关联；在“健康看板”手动执行检查。
4. 在“产品设置 → 数据与交付”查看自检，并按需备份或导出。

## 架构设计

```mermaid
flowchart TB
    U[管理员浏览器] -->|页面 / HTTPS| P[PHP Web 入口与路由]
    X[脚本 / 外部工具] -->|按权限授权的 API 密钥| P
    P --> A[认证、会话与权限控制]
    A --> S[业务服务<br/>资产 / 关系 / DNS / 检查 / 备份]
    S --> D[(本地 JSON 数据与缓存)]
    S --> C[云商适配器]
    C --> V[阿里云 / 腾讯云 / GoDaddy API]
    S --> N[DNS / HTTP / HTTPS 检查]
```

浏览器负责展示和交互；PHP 负责身份校验、业务逻辑和云商调用；数据与缓存保存在部署实例中。不同云商通过适配器接入，避免页面直接处理各家的接口差异。

| 位置 | 职责 |
| --- | --- |
| `public/` | Web 入口、页面、样式与前端脚本；Web 服务只公开此目录。 |
| `app/controllers/` | 接收请求并组织响应。 |
| `app/services/` | 资产、检查、DNS、配置、备份等业务规则。 |
| `app/providers/` | 阿里云、腾讯云和 GoDaddy 的接口适配。 |
| `app/core/` | 路由、认证、HTTP 与数据存储等基础能力。 |
| `config/`、`data/` | 实例配置、凭据、资产和运行数据，不应公开或提交。 |
| `scripts/`、`tests/` | 运维、打包脚本与自动化测试。 |

## 结果与使用边界

- 域名检查包括 DNS、HTTP 和 HTTPS，HTTPS 会校验证书；HTTP 和 HTTPS 均返回 2xx / 3xx 才计为正常。IP 检查访问 `http://IP/`，HTTP 2xx / 3xx 视为正常且不跟随跳转。这不能保证网站业务本身正常。
- 页面上的批量检查由浏览器分批发起，期间需要保持页面打开；也可自行安装下文的主域名定时检查。默认全局检查主域名和 IP，不检查子域名；点击主域名进入详情后可手动检查其子域名，也可以选择“检查所有域名（含子域名）”。每次实际完成的单项检查都会写入日历；只有完整全局检查才生成汇总，中途停止或失败的已完成项仍保留明细。外部告警尚未提供。
- 选择检查所有域名及子域名时，首次读取尚未缓存的云账号 DNS 记录，之后复用按账号及域名保存的快照；可在域名详情或 DNS 管理中手动刷新。只检查缓存中可作为网站访问的子域名；泛解析和仅 TXT / MX 等记录不作为网站检查。
- 日历打卡、待办及全局检查汇总保存在 `data/calendar.json`，逐项检查的当前状态保存在 `data/health.json`，每个资产最近 10 次检查历史拆分保存在 `data/history/<资产ID>.json`（写入时自动迁移，无需手工处理）；均不包含在当前资产备份 / 导出中，资产恢复会清空检查明细与历史。迁移或恢复前请另行安全备份这些文件。新的逐项检查才会出现在日历中，不会自动补录旧历史。
- 当前为单管理员产品，暂无多人角色、客户隔离或内置聊天助手。
- JSON 资产导出和服务器备份不包含云凭据、管理员配置、API 密钥或检查缓存；恢复会全量替换资产，执行前可预览并自动留底。CSV 用于交接，不支持导入。详见 [备份恢复](docs/04-交付与维护/04-备份恢复与版本交付.md)。
- 基础操作记录用于查看已认证写请求的时间、操作者、路由和结果，并非不可篡改审计系统；DNS 变更另有前后值记录。

## 安全、密码与网络

- 登录使用图形验证码和限流。登录页的“记住密码”会把账号和密码**明文保存在当前浏览器本地存储**；取消勾选可删除，请勿在公用设备使用。
- 忘记管理员密码时，在部署服务器的项目目录中运行 `php scripts/reset-admin-password.php`，按提示输入新密码。重置会保留资产和云账号，但原登录会话与 API 密钥失效。
- 云凭据保存在服务器私有配置中。生产环境应使用 HTTPS、最小权限云凭据，并确保 `config/` 与 `data/` 不可从 Web 访问。
- GoDaddy 连接受网络影响时，可在云账号编辑页配置可信的 HTTPS API 转发地址，或在产品设置中配置网络代理。凭据会发送到所配置的转发服务。

## API 与开发

登录后可从产品设置查看接口描述；实例提供 `/api/openapi.json`、`/.well-known/asset-workspace.json` 和 `/llms.txt`。API 密钥按权限范围授权；账号配置、备份和恢复等管理操作仅允许管理员会话。写入接口的具体参数与权限以 OpenAPI 文档为准。

可达性判定只看 HTTP 访问：HTTP 2xx / 3xx 即计为正常，HTTPS 证书或连接问题不改变可达性。独立的“问题中心”页面把待处理事项聚合为一份分级清单：P0 HTTP 检查异常、P1 结果过时、P2 30 天内到期，按类型筛选并可一键批量检查；检查通过后自动移出。HTTPS 证书验证失败、HTTPS 未确认与证据过时的域名在独立的「HTTPS 跟进」页汇总（`GET /api/https-review`），专项跟进。未检查、DNS 失败或网络故障也可能出现在清单中，不能单凭此判断域名没有运营。AI 可使用 `assets:read` 权限读取 `/api/issues` 获取与页面同源的问题清单——每条含稳定问题 ID、证据摘要、解析 IP、云托管域名的 DNS 读取路径与建议动作，可在备注或提案 rationale 中引用问题 ID 记录处理结论，再以 `checks:run` 复查确认问题消失；`/api/operations` 仍提供待运营域名原始视图。检查时间、过期状态和 IP 可能是 CDN 地址，需一并核对。指定新 IP 时，可使用已有 DNS 记录 API 先读取并核对记录，再以 `dns:write` 提交对应 A / AAAA 记录及版本；手工域名需在实际 DNS 服务商操作。

需要让外部 AI 分析当前资产状况时，健康看板的“AI 分析”按钮会基于缓存证据生成一份 Markdown 报告（检查异常域名、HTTPS 未确认域名、异常 IP、30 天内到期及解读指引）。一键「复制提示词 + 报告」会把报告与一份完整的分析要求（异常归类、影响面、按 P0/P1/P2 排序的建议动作、证据不足时的处理）一起复制，粘贴给任意 AI 助手即可直接开始分析；也可只复制报告或下载 `.md`。接口为 `GET /api/health/report`（返回 `markdown` 与 `prompt` 两个字段），加 `?format=markdown` 直接返回报告正文。报告生成过程只读、不触发检查，单表最多列出 50 行，且不包含任何凭据。

AI 全流程接管以两个接口为入口：`GET /api/handover`（`assets:read`）返回当前统计、密钥持有的权限、下一步动作与完整操作序列；`POST /api/proposals`（`proposals:write`）允许 AI 在发现问题时提交 DNS 变更提案（含变更理由与依据）。提案只入队、不写云端；管理员在「产品设置 → 数据与交付 → AI 变更提案」中批准或拒绝，批准时按既有护栏执行（读取云端最新版本、单次写入、回读核实），全过程记录在 DNS 变更与操作记录中。AI 无法绕过审批直接修改云端 DNS。

界面与人看图表、AI 执行操作、监控平台读数各取所需：「检查趋势」页面渲染近 30 天检查趋势（数据来自 `GET /api/trends`，`assets:read`）；监控平台可用同一权限抓取 `GET /api/metrics`（Prometheus 文本格式，`asset_workspace_*` 指标，含资产分布、HTTPS 未确认数、提案状态与检查延迟），接入现有告警与大盘，实现人、AI 与监控的共同治理。

IP 服务器列表可按需查询或重新查询归属地，也可批量查询未缓存的 IP。查询会把目标公网 IP 发送给第三方 [IPWHOIS 免费接口](https://ipwhois.io/documentation)，结果仅为近似位置；数据和查询时间缓存在 `data/ip_locations.json`，不包含在资产备份和导出中。查询失败会保留上次成功结果。AI 可使用 `checks:run` 调用 `POST /api/health/ips/{id}/location`，从 `/api/health` 读取缓存。该第三方接口的免费额度及条款以服务商文档为准。

可配置服务器每天检查一次全部主域名，检查结果会更新列表。以应用数据目录的运行用户安装以下 crontab，并将路径替换为实际路径：

```cron
0 3 * * * cd /path/to/asset-workspace && /usr/bin/php scripts/check-domain-operations.php >> /path/to/domain-check.log 2>&1
```

这项计划需要自行安装，默认不会修改服务器 crontab；检查不修改 DNS。请确保日志路径可写并按需轮转。

全量健康检查、域名访问检测与域名同步也可以转入后台执行：看板的「转后台执行」按钮调用 `POST /api/tasks` 入队（仅管理员会话），任务记录保存在 `data/tasks.json`，关闭浏览器后继续，由同一 crontab 驱动的 worker 逐个认领执行；顶栏胶囊显示排队与进度，`GET /api/tasks` 提供任务列表。启用方式是在上面的 crontab 中追加一行：

```cron
* * * * * cd /path/to/asset-workspace && /usr/bin/php scripts/task-worker.php >> /path/to/task-worker.log 2>&1
```

worker 每次认领一个任务后退出；执行中进程中断（心跳超过 15 分钟）的任务会被标记失败并可重新入队，不会重复写入。未配置该 cron 时任务会保留在队列中，入队不会触发任何网络操作。

改进计划页（#plans）用于功能点的提出、逐条审核与执行跟踪：条目由工作台手动新增或 AI 协助提出（`php scripts/seed-improvement-plan.php` 可写入种子计划），状态流为待审核 → 已通过 → 执行中 → 已完成，驳回需附原因；执行侧只实施「已通过」条目，完成后回填执行结果。接口为 `GET/POST /api/plans`、`PUT/DELETE /api/plans/{id}` 与 `POST /api/plans/{id}/review`（仅管理员会话），记录保存在 `data/improvement_plan.json`。

也可以随时在部署服务器的项目目录运行 `php scripts/generate-health-report.php`，直接在终端输出同一份 Markdown 健康报告（只读缓存证据），便于通过脚本或邮件交给 AI 分析；加 `--prompt` 则输出已内嵌报告的完整分析提示词。
